# interview

작업을 설계하기 전에 **논의(Discuss) 단계를 인터뷰 형식으로 실행**하고, 그 결정을
후속 단계가 그대로 읽어 쓰는 **입력 계약 문서**로 남기는 에이전트 스킬.
**Claude Code**와 **Codex CLI** 두 런타임을 각각 전용 변형판으로 지원한다.

```
/interview  =  무엇을 왜 만들까(혹은 만들지 말까)를 확정한다
/design     =  확정된 결정을 어떻게 만들지로 구체화한다
```

## 왜 필요한가

"불확실하면 물어라" 같은 상시 규칙은 **모델이 불확실함을 자각해야** 발동한다 —
확신에 찬 오해는 그냥 통과해서, 틀린 문제를 잘 푸는 결과가 된다. 설계 문서 안에서
"무엇을 왜"와 "어떻게"가 섞이면 방향을 반박할 시점이 이미 늦고, 대화 속 합의는
세션이 끝나면 휘발된다.

이 스킬은 논의를 **자각과 무관하게 발동하는 단계**로 승격하고, 그 결과를 정본
파일 하나로 남긴다. 핵심은 문서의 각 절이 자기 소비처(design·plan·verify·
milestone)를 주석으로 달고 있어서, 후속 단계를 실행하는 누구든 어느 절을 어디에
쓸지 문서가 스스로 말한다는 점이다.

## 핵심 규칙

- **스킵 게이트** — 해석이 갈리거나 / 비가역이거나 / 성공 기준을 한 문장으로 못
  내리거나 / "안 함"이 유력할 때만 인터뷰를 시작한다. 아니면 design 직행을 권한다.
- **how가 나오면 종료** — 구조·인터페이스·파일 단위 변경이 나오기 시작하면 논의는
  끝난 것이다. 기록을 닫고 design으로 넘긴다.
- **청자의 언어로 묻는다** — 질문·선택지는 개발 지식 없이도 판단할 수 있게 쓴다.
  용어는 그 자리에서 풀고, 트레이드오프는 "이걸 고르면 무슨 일이 생기는가"라는 결과로 설명한다.
- **기각도 기록한다** — 선택지마다 "기각 이유:" 필수. 6개월 뒤 "왜 안 했지"를 막는다.
- **라운드 상한 5** — 상한에 닿고도 결정이 안 서면 논의 부족이 아니라 요구사항
  부재다. 미결로 기록하고 닫는다.
- **쓰기는 결정 기록 하나뿐** — 코드·설계 문서·칸반을 수정하지 않는다.

## 동작 — 5트랙 라운드제 인터뷰

1라운드 = 1주제 = 질문 1~4개(선택지에 트레이드오프 설명 포함). 이미 답이 나온
트랙은 건너뛴다.

| R | 트랙 | 캐내는 것 |
|---|---|---|
| 1 | 문제·동기 | 무엇이 아프고, 왜 지금인가 |
| 2 | 성공 기준 | 무엇이 되면 끝인가 — 검증 가능한 문장으로 |
| 3 | 제약·전제 | 기술 제약, 되돌림 가능성, 기존 결정과의 충돌 |
| 4 | 선택지 반응 | 채택 조건이 붙은 2~4개 선택지에 대한 선호와 이유 |
| 5 | 범위·비목표 | 이번에 안 하는 것 |

산출물은 `discussions/I-<slug>.md` — 배경/성공 기준/제약/선택지/결정/비목표/미결
각 절에 `→ 소비처` 주석이 붙은 결정 기록이다.

## 전제

design→plan→execute→verify 스킬 체인이 있는 프로젝트에서 가장 유기적으로
동작하지만(결정 기록이 각 단계의 입력이 된다), 체인이 없어도 독립적으로 쓸 수 있다.
