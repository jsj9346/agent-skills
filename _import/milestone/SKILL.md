# milestone

**"어디까지 왔나"의 기준선을 파일 하나로 둔다.** `/current-status`가 "지금 열린 것"을 재는
도구라면, 이 스킬은 **"열린 것 중 무엇이 이번 목표이고 목표는 언제 끝나는가"**를 정하는 도구다.

프로젝트 루트의 `MILESTONE.md`가 활성 마일스톤의 정본이다. **활성 마일스톤은 한 번에 하나.**
둘 이상을 열고 싶으면 그것은 마일스톤이 아니라 우선순위 미결이다 — 하나를 고르게 한다.

## 원칙

1. **종료 조건은 명령으로 잰다.** 각 조건에 `검증:` 줄이 붙고 그 줄은 셸 명령, 파일 경로+상태,
   또는 카드/slug의 닫힘이다. "웹 UI 완성" 같은 산문은 `set`에서 **거부하고 되묻는다.**
   산문 조건이 하나라도 남으면 `status`는 다시 감으로 돌아간다.
2. **숫자를 손으로 적지 않는다.** "3/7 완료" 같은 진척은 `MILESTONE.md`에 쓰지 않는다 —
   `status`가 매번 검증 줄을 실행해 계산한다. (neo-agent 칸반 규칙 "보드에 수를 쓰지 않는다"와 같은 이유:
   손으로 유지되는 수는 낡는다.)
3. **소속은 범위 목록으로 정한다.** `MILESTONE.md`의 `범위` 절이 소속 항목의 ID를 든다 —
   `kanban.md`형이면 카드 ID(`K-nnn`), `workstate.md`형이면 그 원장의 항목 ID/slug.
   카드·항목 파일에 필드를 추가하지 않는다 — 66장에 필드를 다는 것보다
   한 파일의 목록이 유지 비용이 낮고, 이 목록이 곧 **"이번엔 안 한다"의 정본**이 된다.
4. **마일스톤 밖 작업은 순위에 오르지 않는다.** `/current-status`가 범위 밖 카드를 `대기`(neo-agent) /
   "마일스톤 외"(sylph)로 표시한다. 이것이 이 스킬의 실제 효과다 — 목표를 적는 것이 아니라
   **목표 밖을 순위에서 빼는 것.**
5. **기존 기록 규약을 건드리지 않는다.** 이 스킬이 쓰는 파일은 `MILESTONE.md`와 `milestones/`
   아카이브뿐이다. 칸반·devlog·plan은 각 프로젝트의 스킬(`/kanban`·`/devlog-add`·`/devnote`)이 쓴다.
   `close`가 devlog에 남겨야 할 것은 **그 스킬을 호출해** 남긴다.

## `MILESTONE.md` 형식

```markdown
# M<n> — <한 줄 이름>

- 상태: 활성
- 설정: YYYY-MM-DD
- 목표: <이 마일스톤이 끝나면 사용자가 무엇을 할 수 있는가 — 한 문장. 기능이지 작업이 아니다>
- 비목표: <의도적으로 이번에 안 하는 것. 다음에 "왜 안 했지"를 막는다>

## 종료 조건

각 조건은 `검증:` 줄로 잰다. 전부 통과 = 마일스톤 종료.

### C1 — <조건 한 줄>
- 검증: `<셸 명령>` → <기대 출력>            ← 셋 중 하나
- 검증: `<파일 경로>` 존재 · 상태 `<값>`
- 검증: 항목 `K-nnn` 닫힘 (`kanban.md`/`workstate.md`에 없고 devlog에 이관)
- 근거: <왜 이것이 조건인가 — 정본 문서 §번호>

## 범위 — 소속 작업

| ID | 어느 조건에 기여 | 비고 |
|---|---|---|
| K-170 | C1·C2 | |

**범위 밖은 `/current-status`가 순위에서 뺀다.** 범위에 넣고 싶으면 이 표에 추가하고 `설정` 날짜
아래에 `- 범위 변경: YYYY-MM-DD <ID> 추가/제거 — <이유>` 한 줄을 남긴다.
```

## 동작 — 인자 `$1`

### `set <이름>` (인자 없음도 같음 — 활성 마일스톤이 없을 때)

활성 마일스톤이 이미 있으면 **거부**하고 `close` 또는 범위 변경을 안내한다.

1. 열린 작업의 정본을 판별한다: 프로젝트 루트의 **`kanban.md`**(칸반 카드형 — 항목 ID는 `K-nnn`) 또는
   **`workstate.md`**(작업 상태 원장형 — 항목 ID/slug는 그 원장의 규약을 따른다). 둘 다 있으면 거부하고
   어느 쪽이 정본인지 묻는다. 둘 다 없으면 `workstate.md` 신설을 제안한다 — 마일스톤은 열린 작업의
   정본 위에서만 성립한다.
2. 열린 작업을 읽는다 — 판별된 정본 전체 + `docs/BACKLOG.md`(있으면).
3. **사용자와 목표 한 문장을 확정한다.** "끝나면 사용자가 무엇을 할 수 있는가"로 묻는다. 작업 이름
   ("웹 UI 구현")이 오면 기능 문장("`neo-agent serve`로 브라우저에서 한 턴을 주고받는다")으로 바꿔 되묻는다.
4. 종료 조건을 **3~7개**로 제안한다. 각각에 검증 줄을 붙이되, 검증 줄은 **실제로 실행해 본다**
   (`(신규)` 대상 제외) — 지금 fail이 나야 정상이고, 명령 자체가 오류나면 조건이 잘못 적힌 것이다.
5. 열린 작업 전체를 훑어 범위 표를 제안한다. **판정을 밝힌다**: 각 카드에 대해 "C<n>에 기여" 또는
   "범위 밖 — <이유>". 애매한 것은 사용자에게 묻는다 — 조용히 빼면 다음 사이클에 되살아난다.
6. `MILESTONE.md`를 쓴다. 이어서 프로젝트 기록 규약대로 남긴다(neo-agent: `/devlog-add`, sylph: `/devnote`).
7. 마지막 줄: `▶ 다음 단계: /current-status priority`

### `status` (또는 `얼마나 남았어`, `남은 거`)

**읽기 전용.** 아무것도 쓰지 않는다.

1. `MILESTONE.md`를 읽고 **모든 `검증:` 줄을 실제로 실행한다.** 기억이나 devlog로 대신하지 않는다.
2. 범위 표의 각 항목이 실물에서 어느 상태인지 정본(`kanban.md`/`workstate.md`)에서 읽는다(레인·상태 필드, 연결된 plan 체크박스·verification verdict).
3. 출력:

```
## M<n> — <이름> · YYYY-MM-DD 기준

| 조건 | 상태 | 근거 (실행 결과) |
|---|---|---|
| C1 … | ✅ 통과 / ❌ 미달 / ⚠ 측정 불가 | `<명령>` → <실제 출력 요약> |

**남은 조건: N개** — <미달 조건의 이름만 나열>

### 범위 작업 상태
| ID | 조건 | 상태 |
|---|---|---|

### 범위 밖인데 최근 손댄 것   ← 없으면 생략
<git log 최근 15개 · 최신 devnote에서 범위 표에 없는 항목을 건드린 흔적. 이것이 목표 이탈 신호다>

▶ 다음 단계: /current-status priority
```

`⚠ 측정 불가`가 나오면 검증 줄이 낡은 것이다 — 고치라고 보고하되 고치지는 않는다(`set`의 범위 변경 절차).

### `close`

1. `status`를 먼저 돌린다. **미달 조건이 하나라도 있으면 거부**한다 — "그래도 닫자"는 조건을 `비목표`로
   옮기는 범위 변경이지 종료가 아니다. 그 절차를 안내하고 멈춘다.
2. 전부 통과면 `MILESTONE.md`의 `상태: 활성` → `상태: 종료 YYYY-MM-DD`, 마지막 `status` 출력을
   `## 종료 시점 측정` 절로 붙인 뒤 `milestones/M<n>-<slug>.md`로 이동한다.
3. 프로젝트 기록 규약대로 종료를 남긴다(`/devlog-add` 또는 `/devnote`).
4. 마지막 줄: `▶ 다음 단계: /milestone set <다음 이름>`

## `/current-status`와의 계약

프로젝트의 `/current-status`는 다음을 한다(이미 통합돼 있어야 하며, 없으면 이 스킬이 통합 방법을 안내한다):

- `MILESTONE.md`가 있으면 첫 절에 `status` 요약 한 줄("M1 · 남은 조건 N개")을 낸다.
- 순위 판정에서 **범위 표에 없는 항목은 순위에 올리지 않고** 별도 표 "마일스톤 외"에 둔다.
  단, 범위 안 조건을 **직접 블록**하는 카드는 예외로 올리되 "범위 밖·블로커"라고 표시한다 —
  그 카드는 범위 변경 후보다.
- `MILESTONE.md`가 없으면 참고 절에 `/milestone set`을 권한다. 강제하지는 않는다.

## 하지 않는 것

- 여러 마일스톤의 로드맵을 그리지 않는다. 다음 마일스톤은 이번 것을 닫은 뒤 정한다.
- 기한을 적지 않는다. 남은 것은 조건 수로 재지 날짜로 재지 않는다 — 날짜가 필요하면 사용자가 산문으로 든다.
- 카드·플랜·devlog를 수정하지 않는다.
