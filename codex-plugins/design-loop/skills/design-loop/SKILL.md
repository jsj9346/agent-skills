# Design Loop — 목표 실행 루프 설계 (Codex CLI판)

> **Codex CLI 전용 스킬이다** — 산출 명령어가 Codex TUI의 `/goal` 슬래시
> 명령을 전제한다. Claude Code 사용자는 상위 디렉토리의
> [SKILL.md](../SKILL.md)를 사용할 것.

> design-harness가 **한 Node가 일을 잘하게**, design-graph가 **여러 Node가
> 함께 일을 잘하게** 만든다면, 이 스킬은 **하나의 목표가 끝까지 도달하게**
> 만든다 — 반복의 제어 구조(무엇을 관찰하고, 언제 재시도하고, 언제
> 멈추는가)를 설계한다.

## 권장 실행 모델

- **이 스킬(설계)**: 상위 추론 모델(GPT-5 계열 이상, reasoning effort
  medium+). 루프가 고위험(비가역 작업·장시간·비용 큰 재시도)이면 최상위
  모델/high effort 권장 — 설계 오류가 반복 횟수만큼 증폭된다.
- **루프 실행 모델**: /goal은 현재 세션 모델로 실행된다. 권장은 **반복 1회
  작업의 복잡도**로 판정한다 — 열린 결정을 닫거나 비가역이면 상위 모델/high
  effort, 계약이 확정돼 따라가면 되면 중간, 기계적 반복·조회면 하위 모델.
  경계면 오류 비용이 큰 쪽. 세션 모델과 안 맞으면 `/model` 또는
  `-c model=...` 변경을 함께 권고한다. 단계별 서브에이전트 위임은 넣지
  않는다 — Codex CLI에는 Claude Code Agent 도구의 모델 오버라이드 등가물이
  없다(Claude Code판 전용).

## 대상 루프 형태와 Codex /goal의 동작

```
Goal → Observe → Decide → Act → Verify → 성공했는가?
                   ↑                        │
                   └──── No: 수정/재시도 ────┘   Yes → Stop
```

`/goal <objective>`는 Codex TUI 슬래시 명령이다 (feature `goals`, stable —
목록에 안 보이면 `codex features enable goals`). objective는 스레드 상태로
붙어 여러 턴에 걸쳐 유지되며, Codex가 stopping condition 도달을 확신할 때
스스로 완료 처리한다. 라이프사이클: `/goal`(상태 확인) · `/goal pause` ·
`/goal resume` · `/goal clear`. 공식 권장형은 "Complete [objective] without
stopping until [verifiable end state]"다.

**Claude Code판과의 핵심 차이**: Codex에는 `+Nk` 토큰 지시자·비용 상한
플래그가 없다 (0.148.0 기준). 따라서 **예산은 objective 텍스트 안에 중단
규칙으로 넣는다** — 런타임 강제가 아니라 프롬프트 강제(soft)임을 사용자에게
고지한다.

## 원칙 (하드 레일)

1. **판정 없는 설계 착수 금지** — 작업을 받으면 먼저 루프 사이클 구현이
   가능한지 판정한다(절차 0단계). 가능 판정 전에는 인터뷰·설계를 시작하지
   않고, 불가 판정 시 설계 없이 불가 사유를 보고하고 종료한다.
2. **설계 없는 goal 실행 금지** — 성공 기준·탈출 조건·예산이 확정되기 전에는
   /goal 명령어를 제안하지 않는다.
3. **증거 없는 Verify 금지** — 성공 기준마다 외부 검증 가능한 증거(테스트
   출력·diff·상태 조회)를 명시한다. 자기보고("됐다")는 Verify가 아니다.
4. **탈출 조건은 성공만이 아니다** — SUCCESS / BLOCKED(외부 조건 — 재시도
   않고 중단·보고) / FAILED(상한 내 미달) / ESCALATED(권한·판단 경계 —
   사람에게 반환)를 objective에 모두 반영한다. 특히 Codex는 판정을 실행
   모델 스스로 하므로 중단 조건을 더 명시적으로 적어야 한다.
5. **재시도는 반복이 아니라 수정이다** — 실패 시 원인 분석 후 접근을 바꿔
   재시도하게 명시한다. 같은 실패 2회 반복 시 중단·보고.
6. **예산 필수** — 최대 반복 횟수와 중단 규칙(예산 조항) 없는 objective는
   제안하지 않는다. 런타임 상한이 없으므로 이 조항이 유일한 폭주 방지다.
7. **루프 하나 = 목표 하나** — 목표가 둘 이상이면 나누거나 design-graph로
   승격한다.
8. **복붙 한 줄 원칙** — 최종 산출물은 **코드블록 하나에 담긴 한 줄
   명령어**다. 줄바꿈 없이, 코드블록 안에 명령어 외 텍스트를 섞지 않는다.
   설명은 코드블록 밖에 쓴다.

## 절차

### 0. 루프 적합성 판정 (게이트)

설계에 앞서, 사용자가 입력한 작업이 **루프 사이클(Observe → Decide → Act →
Verify → 재시도/종료)로 구현 가능한지** 먼저 검토하고 가능 여부를 판정한다.
네 항목 모두 통과해야 **가능**이다: **종료 상태 정의 가능**(외부 증거로
판정 가능한 종료 상태 — 주관 판정만 가능한 목표는 불가) / **관찰 가능**
(매 반복 진행 상태를 관찰할 신호 존재) / **반복이 유효**(실패 → 수정 →
재시도로 개선되는 구조 — 일회성 작업·재시도 무의미한 비가역 작업은 불가) /
**Agent 실행 가능**(Act가 도구·권한 범위 안 — 매 반복 사람의 물리적 행동·
외부 승인 필수면 불가).

- **가능** → 판정 결과를 한 줄로 고지하고 1단계(루프 사이클 설계)로 진행한다.
- **불가능** → **불가 판정 메시지와 이유**(어느 항목이 왜 실패했는지)를
  출력하고 설계 없이 종료한다. 가능하면 대안(일회성 실행·목표 재정의·분할
  또는 design-graph·design-harness)을 한 줄 덧붙인다.
- 정보 부족으로 판정 자체가 안 되면 지어내지 않고 사용자에게 묻는다.

### 1. Goal 인터뷰 → 성공 기준

사용자에게 묻고 (한 번에 몰아서), 답을 확정한다: 목표 → 검증 가능한 성공
기준 + 기준별 증거(실행 명령까지) / Open-ended 목표에는 Satisficing
Condition / Invariants(절대 금지) / 사람 개입 지점. 답하지 못하는 항목은
비워 둔다 — 지어내지 않는다. 성공 기준의 증거가 빈 채로는 명령어를 제안하지
않는다.

### 2. 단계별 계약 설계

Observe(무엇을 관찰) / Decide(판정 기준) / Act(허용 범위 — Invariant 원천
배제) / Verify(기준별 검증 명령)를 각각 한 구절로 확정한다 — objective에
그대로 들어간다.

### 3. 재시도 정책

최대 반복 횟수(권장 3–5회; 초과 필요 시 목표 분할 제안) / 반복 간 수정
규칙(가설 수정·범위 축소·접근 변경) / 에스컬레이션(같은 실패 2회·BLOCKED·
Invariant 근접 시 중단·상태 보고).

### 4. Budget — 중단 규칙 산정

- 반복 1회 작업량을 추정하고(소형: 단일 파일+테스트 / 중형: 멀티 파일+빌드 /
  대형: 탐색+검증 루프), **최대 반복 횟수**와 **시간 상한**(예: "2시간 경과
  시 중단하고 진행 상황 보고")을 정한다.
- 이 조항은 objective 텍스트에 들어간다 — 런타임 강제가 아니므로, 고위험
  루프라면 approval/sandbox 정책(비가역 명령 사전 차단)을 코드블록 **밖**에서
  함께 안내한다. 진행 관찰은 `/goal`(상태)·중단은 `/goal pause`/`clear`임도
  안내한다.

### 5. 명령어 조립 + 제안

1–4단계 결과를 공식 권장형에 맞춰 **한 줄**로 조립한다 — stopping
condition(증거 포함)이 앞에 오게:

```
/goal Complete <목표 한 줄> without stopping until <검증 가능한 종료 상태>. 성공 기준(모두 증거로 검증, 전부 PASS 시에만 완료): (1) <기준>=<검증 명령/증거> (2) <기준>=<증거>. 루프: <Observe> 관찰 → <Decide 기준> 판단 → <Act 범위> 실행 → <Verify 명령> 검증. 실패 시 원인 분석 후 접근을 수정해 재시도(최대 N회). 예산: 반복 N회 또는 <시간 상한> 초과·같은 실패 2회·외부 요인 차단·권한 경계 도달 시 중단하고 진행 상황 보고. 금지: <Invariants>
```

제안 전 자가 점검: (a) 한 줄인가 (b) stopping condition이 검증 가능한가
(c) 성공 기준마다 증거가 있는가 (d) 반복 상한·시간 상한·중단 조건이
있는가. 통과하면 코드블록 하나로 제시하고, 필요한 사전 조치(`codex features
enable goals`·모델 변경·sandbox 정책)는 블록 밖에 한 줄로 덧붙인다.

## 산출물이 아닌 것

- **문서를 만들지 않는다** — 산출물은 복붙 명령어 한 줄이다.
- 루프를 **실행하지 않는다** — 실행은 /goal 런타임의 몫이다.
- 멀티 루프 오케스트레이션(design-graph)·Agent 환경(design-harness)을
  설계하지 않는다.
