# explain

작업·문서·이슈·코드를 **개발 지식이 없는 사람의 눈높이로 설명하는** 에이전트
스킬. **Claude Code**와 **Codex CLI** 두 런타임을 각각 전용 변형판으로 지원한다.

다른 스킬들이 "무엇을 할까"를 정한다면, 이 스킬은 **"그게 대체 무슨 말인가"**에
답한다. 산출물은 코드도 문서도 아니고 **이해**다.

```
설계 스킬   =  무엇을 만들지 정한다
리뷰 스킬   =  만든 것이 맞는지 본다
explain     =  그게 무슨 말이고 왜 해야 하는지 알게 한다
```

## 왜 필요한가

에이전트가 만든 계획·이슈·설계 문서는 대부분 **이미 아는 사람**을 향해 쓰여
있다. 정작 그 작업을 승인할 사람이 "이게 왜 필요한지" 모르면, 판단이 아니라
추인만 남는다. 이 스킬은 그 간극을 메운다 — 전문용어를 그 자리에서 풀고,
필요성을 **"안 하면 무슨 일이 생기는가"**라는 구체적 사고 시나리오로 바꾼다.

## 핵심 규칙

- **지어내지 않는다** — 정본 문서를 실제로 열고 설명한다. 문서에 없으면
  "여기엔 안 적혀 있다"고 말한다. 초심자는 검증할 수 없으므로, 이 스킬의
  지어내기는 다른 어떤 스킬의 지어내기보다 오래 살아남는다.
- **비유는 하나, 같은 세계로 끝까지** — 그리고 **깨지는 지점을 한 줄 붙인다**
  (*"여기까지만 맞는 비유다"*). 안 떠오르면 억지로 만들지 않고 구체적 예시
  하나로 대신한다.
- **"왜"는 사고 시나리오로** — "확장성이 좋아진다"는 이유가 아니다.
  *"이 값을 바꾸려면 파일 40개를 손으로 고쳐야 하고, 하나라도 놓치면 조용히
  틀린 답이 나온다"*가 이유다.
- **쉬움 ≠ 틀림** — 정확도를 깎아서 쉽게 만들지 않는다. 지금 몰라도 되는 것은
  틀리게 말하는 게 아니라 "지금은 몰라도 된다"고 명시하고 미루는 것이다.
- **읽기 전용** — 설명 대상을 수정하지 않고, 기록도 남기지 않는다. 설명은
  결정이 아니다.
- **프로젝트 은어를 빠뜨리지 않는다** — 초심자에게는 업계 용어보다 그 팀끼리
  쓰는 말이 더 막힌다. 검색해도 안 나오기 때문이다.

## 인자

| 대상 | 동작 |
|---|---|
| 이슈·카드 ID (`#42`, `K-042`) | 그 항목 + 항목이 가리키는 정본 문서까지 열어 설명 |
| 문서 경로 · `문서.md §3.2` | 그 문서(또는 그 절)가 무엇을 정한 것인지 |
| `경로:줄번호` | 그 코드가 하는 일. 한 줄씩 번역하지 않고 덩어리의 목적부터 |
| 용어 | 뜻 + **이 프로젝트에서 그게 왜 중요한지** |
| (없음) | 직전 대화에서 방금 한 작업 |

깊이는 두 번째 인자로 조정한다: `쉽게` (비유 중심, 코드 없음) · (기본) ·
`깊게` (구현 세부·대안·레퍼런스 구현까지, **깊어져도 용어는 계속 푼다**).

## 출력 뼈대

절 제목이 매번 같다 — 형식이 바뀌면 어디를 봐야 할지 다시 배워야 한다.

```
## 한 줄로 말하면          <- 전문용어 0개짜리 한 문장
## 지금 무슨 상황인가
## 비유하자면
## 실제로 무엇을 하는가
## 왜 필요한가 — 안 하면 무슨 일이 생기는가
## 이 설명에 나온 말들      <- 용어 | 뜻 | 이 프로젝트에서는
## 끝나면 무엇이 달라지나
## 더 보려면
```

마지막엔 항상 **«아직 안 물어본 것»**(이어질 질문 후보 2~3개)과 **«다음 명령»**을
붙인다. 초심자는 «무엇을 모르는지 모르는» 상태이므로, 다음 질문을 대신
만들어주는 것이 설명의 일부다.

## 구조

```
explain/
├── SKILL.md          # Claude Code 전용
└── codex/
    └── SKILL.md      # Codex CLI 전용
```

같은 원칙·절차이며, 각 런타임의 호출 형식과 지침 파일 관례(스킬·커스텀 커맨드
↔ `$HOME/.agents/skills`·`$스킬명` 호출·AGENTS.md 자동 로딩)에 맞춰 내용만
다르다.

## 설치 — Claude Code

```bash
git clone https://github.com/jsj9346/explain ~/.claude/skills/explain
```

사용: `/explain <대상> [깊이]` 또는 "이거 쉽게 설명해줘" 등 자연어 호출.

## 설치 — Codex CLI

```bash
git clone https://github.com/jsj9346/explain /tmp/explain
mkdir -p ~/.agents/skills
cp -r /tmp/explain/codex ~/.agents/skills/explain
```

사용: `/skills`에서 선택, `$explain <대상> [깊이]`로 명시 호출, 또는 요청이
description과 매칭되면 자동 호출.

## 하지 않는 것

- **대상을 수정하지 않는다** — 오류를 발견하면 지적만 하고, 어느 작업이 그
  수정의 주인인지 알린다.
- **기록을 남기지 않는다** — 단 설명 도중 사용자가 새 판단을 내리면 그것은
  기록 대상이고, 그 레포의 기록 스킬·절차로 넘긴다.
- **가르치려 들지 않는다** — "당연히 아시겠지만"을 붙이지 않는다. 몰라서 물은
  것이다.
- **하위 세션·서브에이전트에 위임하지 않는다** — 설명은 대화의 맥락 전체가
  재료이므로, 그 맥락을 못 받는 쪽은 이 일을 할 수 없다.
