# verify

작업물(코드·문서·설정)을 프로젝트의 **정본 문서**(설계 문서·스펙·계약)에 대조해 독립
검증하고, **판정 리포트를 문서 파일로** 남기는 에이전트 스킬. **Claude Code**와
**Codex CLI** 두 런타임을 각각 전용 변형판으로 지원한다.

```
/execute  =  플랜대로 만든다
/verify   =  만든 것이 계약대로인지 판정한다 (수정은 하지 않는다)
```

## 왜 필요한가

구현을 보고 기대값을 읽어내는 검증은 아무것도 검증하지 않는다. 이 스킬은 순서를
강제한다 — 정본에서 계약을 뽑고, 계약에서 기대값을 도출하고, 그 다음에야 실물을 본다.
구현과 문서가 다르면 검증은 문서 편에 선다.

그리고 판정을 **대화가 아니라 문서로** 남긴다. 검증은 컨텍스트가 길어지는 작업이라
요약·세션 단절로 "대조한 사실 자체"가 유실되기 쉽다. 그래서 리포트 파일을 검증 **시작
전에** 골격으로 개설하고, 항목 하나를 대조할 때마다 그 자리에서 갱신하며, 중단하더라도
"여기까지 봤다"를 남기고 닫는다.

## 핵심 규칙

- **리포트가 산출물이다** — `plans/YYYYMMDD-<대상>-verify-report.md`
  (`plans/`가 없으면 `reports/`). 발견이 없어도(그린) 남긴다: 무엇을 대조해서 그린이
  나왔는지가 그린의 내용이다.
- **계약 항목 목록을 먼저 채운다** — 목록 없이 발견만 모으면 대조하지 않은 항목이
  그린으로 오인된다.
- **판정은 세 등급** — 계약 위반 / 문서 부정확 / 미규정(임의 판정하지 않고 판정 필요로
  올린다).
- **수정하지 않는다** — 검증자와 수행자가 같아지면 독립성이 사라진다. 수정 여부는
  사용자가 정한다.
- **발견 1건 = 작업 원장(`kanban.md`·`workstate.md`) 항목 1개** — 리포트만 남기면
  "이 판정이 아직 안 쓰였다"는 상태가 유실된다.
- 마무리의 마지막 줄은 **권장 모델 + 다음 명령**(리포트 경로 포함) 제안이다.

## 리포트 형식

종결 시 다섯 절: **집계** · **발견 상세**(등급·재현·§근거·수정 제안) · **판정 필요 목록** ·
**커버리지 구멍** · **검증하지 않은 것**. 마지막 절이 리포트의 신뢰를 만든다 — "검증했다"의
범위가 정직해야 한다.

## 설치

```bash
# Claude Code
/plugin marketplace add jsj9346/agent-skills
/plugin install verify@jsj9346-skills

# Codex CLI
codex plugin marketplace add jsj9346/agent-skills
codex plugin add verify@jsj9346-skills
```

## 전제

대조할 정본 문서(설계 문서·스펙·계약)가 있는 프로젝트. design→plan→execute→verify
체인을 쓰는 프로젝트면 후속 명령까지 이어지고, 아니어도 리포트 산출까지는 단독으로
동작한다. 정본이 아예 없으면 설계 문서 작성을 먼저 제안한다.
