# current-status

프로젝트의 작업 원장·기록·실물(코드베이스·git)을 **교차 검증**해 현재 진행 상황을
판정하고, 남은 작업의 우선순위와 이번 사이클 묶음을 제안하는 에이전트 스킬. **Claude
Code**와 **Codex CLI** 두 런타임을 각각 전용 변형판으로 지원한다.

```
/current-status  =  지금 어디까지 왔고, 다음에 무엇을 해야 하나
/milestone       =  그중 무엇이 이번 목표이고, 목표는 언제 끝나는가
```

## 왜 필요한가

기록 하나만 읽으면 놓친다 — 원장은 손으로 갱신되므로 실물보다 낡고, 작업 노트에만 있고
요약 기록에 없는 진행이 생기고, 상태가 `진행 중`으로 굳은 리포트는 중단된 사이클이다.
이 스킬은 여러 소스를 교차해 그 불일치를 잡고, **복붙 가능한 다음 명령 한 줄**로 다음
사이클을 연다. 새 세션의 맥락 복구 진입점이기도 하다.

## 핵심 규칙

- **읽기 전용** — 원장이 실물과 어긋나 있어도 고치지 않고 보고한다. 고치는 것은 작업
  스킬의 일이다. 제안한 작업을 바로 시작하지도 않는다.
- **게이트 → 정렬 → 묶음** — 순위를 매기기 전에 착수 불가 항목을 걸러낸다:
  G0 마일스톤 범위(`MILESTONE.md`) / G1 트리거 대기(원문 인용) / G2 선행 블록(설계가
  먼저) / G3 사용자 액션. 남은 것만 네 축(하류 레버리지·정정 비용·착수 비용·묶음 이득)
  으로 정렬하되 **점수를 합산하지 않고 축의 이름을 댄다.**
- **없는 일을 발명하지 않는다** — 제안의 출처는 원장이다. 원장에 없는 후보는 "원장에
  없음"으로 표시한다.
- **오래 열린 항목은 순위가 아니라 재판정** — 3사이클 이상이면 "할 것인가 / 닫을
  것인가"를 묻는다.
- 모든 제안에 **정본 문서 경로 + 권장 모델 + 복붙 가능한 다음 명령**을 붙인다. 보고의
  마지막 줄은 항상 "지금 실행할 명령"이다.

## 전제

interview→make-design→make-plan→execute→verify 체인의 관제 지점 — 각 스킬이 사이클을
닫으며 "다음 작업 후보 조회"로 넘길 때의 수신처다. 작업 원장(`kanban.md`·`workstate.md`)
이 있으면 가장 잘 동작하고, `MILESTONE.md`가 있으면 `/milestone`의 범위 표를 순위
기준선으로 쓴다.
