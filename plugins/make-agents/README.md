# make-agents

프로젝트(워크스페이스)의 목적에 맞는 **서브에이전트 팀을 설계·생성**하고,
**스킬 호출을 담당 에이전트로 라우팅**하는 에이전트 스킬. **Claude Code**와
**Codex CLI** 두 런타임을 각각 전용 변형판으로 지원한다.

워크스페이스 문서를 먼저 읽고, 문서로 답할 수 없는 항목만 인터뷰로 채운 뒤,
역할마다 다음을 갖춘 에이전트를 만든다:

- **역할** — 책임 한 문장 + 하지 않는 것 (역할 단일성: 에이전트 하나 = 책임 하나)
- **도메인 지식** — 그 프로젝트의 실제 규칙·용어·파일 위치 (일반론 금지)
- **성격·태도** — 역할에서 기능적으로 도출된 작업 스탠스 (리뷰어=회의적,
  탐색가=발산적 …). 장식용 페르소나는 만들지 않는다
- **기본 AI 모델** — 작업 난이도 × 오류 비용 매트릭스로 배정하고 근거를 주석으로
  남긴다. 애매하면 낮은 티어
- **출력 계약** — 호출자에게 무엇을 어떤 형태로 돌려주는지

## 스킬 → 에이전트 라우팅

특정 스킬을 호출할 때마다 담당 에이전트가 작동하도록, 런타임의 **공식
메커니즘을 정본**으로 쓴다:

- **Claude Code**: SKILL.md frontmatter의 `context: fork` + `agent: <이름>` —
  스킬이 지정 서브에이전트에서 실행된다. fork가 불가한 스킬(대화 맥락 필요)만
  본문의 위임 지시로 대체한다.
- **Codex CLI**: 에이전트는 커스텀 에이전트 TOML(`.codex/agents/*.toml` —
  model·reasoning effort·sandbox 지정 가능)로 만든다. 스킬 frontmatter에는
  에이전트 바인딩 필드가 없으므로(문서상 부재 확인), 라우팅 정본은 **스킬
  본문의 명시적 스폰 지시**이며, 독립 프로세스가 필요하면 `codex exec
  --profile/-m`으로 위임한다 — 상세는 [codex/SKILL.md](codex/SKILL.md).

라우팅 룰은 한 곳(강제층)에만 산다 — 같은 룰을 지침 문서에 중복 기재하지 않는다.

## 핵심 원칙

- **문서 우선, 인터뷰는 갭만** — 지어내지 않는다. 원재료가 없으면 팀도 얇아진다.
- **관측 근거** — 관측된 반복 작업 또는 명시된 요구에만 에이전트를 만든다.
  팀 상한 기본 5, "혹시 몰라서"는 근거가 아니다.
- **최소 도구 권한** — tools는 역할에 필요한 것만 allowlist로.
- **토대 검증** — 런타임 기능은 추정하지 않고 확인된 것만 쓴다. 버전 의존
  기능은 버전을 병기한다.
- **승인 후 생성** — 팀 매니페스트 제시 → 승인 → 생성 → 위임 시나리오 검증.

에이전트는 많을수록 좋은 것이 아니다 — 성공 기준은 "몇 명을 만들었나"가 아니라
**"관측된 작업에 맞는 가장 작은 팀을 찾았나"**다.

## 설치

```bash
# Claude Code (글로벌)
git clone https://github.com/jsj9346/make-agents ~/.claude/skills/make-agents
```

Codex CLI 사용자는 저장소의 `codex/SKILL.md`를 Codex의 스킬 경로에 배치한다.

## 사용

```
/make-agents            # 팀 설계·생성 (기존 팀이 있으면 진단 모드 겸함)
```

트리거 예: "에이전트 만들어줘", "서브에이전트 구성", "에이전트 팀 설계",
"이 스킬을 에이전트에 연결해줘".
